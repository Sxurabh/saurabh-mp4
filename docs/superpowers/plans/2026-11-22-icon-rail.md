# Icon Rail Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the booking button and add a scale-aligned header with name/role on the iPod's left edge and Instagram/email/About me icons on its right edge.

**Architecture:** The existing viewport fitter sets `--ipod-scale` on a new `.device-frame` wrapper that contains both the header and the scaled stage. The header is exactly `415px * scale` wide and centered in the `439px * scale` footprint, so its edges coincide with the iPod body. The npm package stays untouched.

**Tech Stack:** Next.js 16 App Router, TypeScript, plain CSS, inline SVG icons, `ipod-simulator`.

**Spec:** `docs/superpowers/specs/2026-11-22-icon-rail-design.md`

## Global Constraints
- No new dependencies; do not modify `node_modules/ipod-simulator`.
- Keep the single-screen, no-scroll layout at all tested viewports.
- About me is a visible inert placeholder; no behavior until further instruction.
- Instagram/email URLs come from `site.links` and `site.email` in `lib/site.ts`.

## Review Focus
- Short landscape (667×375): header must fit inside the scaled body width with tappable icons.
- Narrow portrait (320×568): name and three icons must not overflow the header.
- Alignment: header left/right edges must match the iPod body's rendered edges at every size.
- Keyboard/focus: icon links and the About me button need visible focus rings and labels.
- No regressions: no scroll, no console errors, iPod and shadow fully visible.

### Task 1: Move scale to a frame wrapper and rebuild the header

**Files:**
- Modify: `app/components/IPodPlayer.tsx`
- Modify: `app/page.tsx`
- Modify: `app/globals.css`

**Interfaces:**
- Consumes: `IPodPlayerProps { songs: Song[]; playlists: Playlist[]; artists: Artist[] }`; `site` from `@/lib/site`.
- Produces: `IPodPlayer` with optional `children: ReactNode` rendered inside `.device-frame` above `.stage`; `--ipod-scale` set on `.device-frame`.

- [ ] **Step 1: Refactor `IPodPlayer`**

Add `children?: ReactNode` to the props. Move the fitter ref from `.stage` to a wrapping `<div className="device-frame">` that renders `{children}` followed by the existing `.stage` section. Keep the chrome probe, fitter math, and error message unchanged; set the CSS variable on the frame.

- [ ] **Step 2: Rewrite the header in `app/page.tsx`**

Pass the header as children of `<IPodPlayer>`. Render identity (`site.name` + accent + `site.role`) and a `<nav className="icon-rail">` with: Instagram link (`site.links[0].href`, `aria-label="Instagram"`, `target="_blank"`, `rel="noopener noreferrer"`), email link (`mailto:${site.email}`, `aria-label="Email"`), and `<button type="button" aria-label="About me">` with no handler. Use inline SVG icons (camera, envelope, person). Delete the "Book a show" anchor.

- [ ] **Step 3: Update `app/globals.css`**

Change `.stage` fallback `--ipod-scale` rules to `.device-frame`; make `.device-frame` a centered flex column. Set `.topbar { width: calc(415px * var(--ipod-scale)); margin: 0 auto; justify-content: space-between; }`. Use `max()` for header font sizes and icon target sizes (26–36 px) so they stay usable at small scales. Remove `.book-button` rules and add `.icon-rail`/`.icon-button` styling with visible `:focus-visible` rings. Keep stage/ipod/shadow rules and short-screen chrome rules intact.

- [ ] **Step 4: Verify build and lint**

Run: `npm run lint && npm run build`
Expected: both exit 0.

- [ ] **Step 5: Verify in browser**

Run the Playwright check at 320×568, 375×667, 390×844, 430×932, 768×1024, 1280×800, and 667×375. Assert: no scroll in either axis; no "Book a show" text; header left edge and right edge match the iPod body's `getBoundingClientRect()` within 2 px; all three icons visible and inside the viewport; no console/page errors.
